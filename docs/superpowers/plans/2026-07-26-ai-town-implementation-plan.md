# AI Town 代码实现计划

> **目标**：基于已完成的 188 份设计文档，按域顺序实现 AI 小镇游戏的完整功能。

**开始日期**：2026-07-26  
**技术栈**：Python FastAPI + TypeScript Phaser 3 + SQLite  
**开发模式**：按文档域依赖顺序，逐域实现并单元测试

---

## 一、实现原则

1. **严格遵循文档契约**：每个模块的实现必须符合对应文档中的 RULE/DES/REQ 定义
2. **测试先行**：每个域实现完成后，编写对应的单元测试（对照文档中的 TEST-* ID）
3. **渐进式验证**：完成一个域后人工验证基本功能，确认无误再继续下一个
4. **接口契约优先**：前后端共享 Schema 定义，通过 TypeScript 类型和 Python Pydantic 保证一致性
5. **权威后端**：所有世界状态变更必须经过后端验证，前端只负责渲染和输入

---

##二、技术架构确认

### 后端技术栈
- **Python 3.11+**
- **FastAPI**：REST API + WebSocket
- **SQLite**：世界状态持久化
- **Pydantic**：数据验证和 Schema
- **pytest**：单元测试
- **httpx**：DeepSeek API 调用

### 前端技术栈
- **TypeScript 5.x**
- **Phaser 3**：游戏引擎
- **Vite**：构建工具
- **Vitest**：单元测试
- **Zod**（可选）：运行时类型验证

- **Python**：遵循 PEP 8，使用 Black 格式化
- **TypeScript**：遵循 ESLint + Prettier
- **命名**：使用文档中的术语和标识符，保持一致

### Git 提交规范
```
<type>(<scope>): <subject>

feat(map): 实现导航网格和 A* 寻路
fix(ai): 修复 ActionProposal 验证错误
test(combat): 添加回合顺序测试
docs(readme): 更新启动说明

Co-Authored-By: Claude <noreply@anthropic.com>
```

### 测试覆盖率目标
- 核心逻辑模块：≥ 80%
- 数据验证和 Schema：≥ 90%
- UI 和渲染：人工验收为主

## 六、风险和应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| DeepSeek API 不稳定 | AI 决策失效 | 强化 Utility AI Fallback，本地缓存 |
| 前后端 Schema 不一致 | 通信失败 | 共享 Schema 定义，自动生成类型 |
| 地图资源生成质量不足 | 视觉体验差 | 先用占位符，后期迭代美术 |
| 性能问题（大量居民） | 卡顿 | Active/Warm/Background 分层，限制同屏居民数 |
| 测试覆盖不足 | 上线后 Bug 多 | 每个域实现后强制编写测试 |
